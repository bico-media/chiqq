# Chiqq performance results

Generated by `test/performance/run.sh` (`node run.js`). Do not edit by hand.

- Date: 2026-11-04
- Machine: Apple M1 Pro, 8 cores, 16 GB, darwin 24.6.0
- Runtimes: node v24.22.1, bun 1.4.3, deno deno 2.6.3 (stable, release, aarch64-apple-darwin)
- Libraries: chiqq 2.2.0 (src), p-queue 10.0.0, p-limit 7.3.3, fastq 1.20.3, async 3.2.6, bottleneck 2.19.5, promise-pool 3.3.0
- Each case runs in 3 fresh processes: 5+ warmup runs (at least 300 ms) each, then up to N timed runs (capped at a 20s budget per process, killed after 60s). Cases slower than 1s get a single process.
- Each cell: time relative to the fastest library on that runtime (1.00x is the fastest, 1.50x took one and a half times as long), then the median time over all pooled runs, then the spread: half the interquartile range, so most runs land within that many percent of the median. Differences smaller than the spread are noise.
